# 万仙之一 · 当前设计与实现

## 产品中心

当前版本以「有限起点、漫长岁月、具体人物与持续后果」为核心。操作简洁不等于取消规则；修炼、资源和风险继续真实存在，但玩家首先面对生活处境，不必年年清空行动次数。

2026-10-30用户授权实施人生机制改造并上线。这取代此前以修炼进度、法宝和境界准备占据首屏、默认十六岁开局的布局；保留像素美术、既有修仙系统和旧存档。源码是已实现行为的权威，不能把未来设想写成现有功能。

## 出生与主页

出生默认零岁，家世和地域随机，姓名可空；节奏30／60分钟。详细出身、时代、修行道路、灵根、种子、快速启程和日常照料开关收在可展开设置，不再要求逐项配置。

主页「人生」依次呈现短场景、生活方向、最近的重要经历、四位同世人物和往事。数值与高级动作在「修行与事务」展开；宗门、洞府、行囊、地图、秘境和此生详情仍可进入。手机保留人生／机缘／经营／此生四主入口，桌面十页导航保留。

最近经历来自已提交日志，不生成未发生的文案。人物卡显示实际境界与离场状态，点击查看与该人物关联的已发生记录。世界时运仍每20年结算，但周期性播报不再默认标记为人生大事，避免淹没个人经历。

沿用青蓝与月夜像素主题，本地场景/头像/物品图集，动态内容由DOM渲染。移动正文约12–13px，主场景标题约18px，关键触控至少44px；详细信息可展开，不用教学段落或设计辩解填充页面。眼前成本、失败风险、约束和不可用原因应清楚展示。

## 生活方向和控制边界

`Game.direction`可缺省，取值seek／roam／belong／peace，分别是问道、远游、相守、自处。新出生由`BirthConfig.guided`显式开启；旧存档缺省保持原手动模式，不自动修改玩家旧安排。

年度开始时，`arrangeLife`先考虑真实健康、道心和生计，再考虑未完成准备及生活方向。问道更多闭关，远游更多历练，相守更多访友，自处更多读书和静养。没有免费的额外资源，恢复、工作和修炼都经过原年度公式。手动选择七种年度重心会退出日常照料。

具备生活方向时，年度结算后、未触发待决事件且健康/道心/资源/修为/调息满足要求，才使用原突破动作尝试普通破境。失败仍消耗费用、修为和身心；不会调整随机数来保证成功。日常照料不自动加入宗门、购物、建造或替玩家进入秘境。

自动模式不能回答turning事件。化神修为圆满后先出现`life-heaven`，玩家决定开始叩关或暂留人间。暂留只阻止自动最终突破，不关闭手动冲关。未取得选择时不能通过普通自动照料直接飞升。

## 人物因果事件

`lifelines.ts`提供20个有限、条件式事件，静态注册表负责存档ID，`getLifeEvent`根据当前人物、原有选择和存活状态构造可读情境。渲染不抽随机数、不提前发奖励。全局人工事件间隔仍至少6年，童年固定节点优先。

早年包括渡口约定、共同丹药、家族长约、剑谱分歧、相聚和送别。后续使用真实`seen`年龄与选择旗标，部分入口要求原人物仍活着；人物离场后使用原名的手稿、遗物和旧约，不替换演员或复活。

具体机械后果：

- 共同丹药归自己时获得修为；赠药/合炼成功改善指定药师同道的后续成长倍率和历练风险，并影响该人物关系。不保证生存，也不预设报恩奖金。另炼一炉使用真实灵石与种子概率，失败损失资用。
- 家族长约每年增加4灵石，并使修炼基准乘0.92。续约事件可结束长约，保留历史选择、停止收入并恢复这部分修炼时间。
- 渡口歇脚屋支付一次费用并持续每年2灵石供养，地图和原人物的关联写入后续，不是一次领奖提示。
- 剑谱的保密约定、先前分歧和当前关系改变之后可选办法；信任足够且本人仍在时才能重新商议公开范围，违约影响同一个人物的关系。最初各行其道者收到的是对方后来新写的谱，不假定早年取得了旧传承。
- 留下开放书册、传统师承或个人行记产生不同后续。只有行记会遇到读者分支，不凭空创造门人；学堂持续由自己主持时额外占用5%的修炼基准。

继承、改写、分流、名字被遗忘、传说与本人、后来者和旧地变化跨越数百年。后续时间从前事实际发生年龄计算，而不是所有人生固定同年发生。人物早逝或玩家提前结卷可能让部分故事不再发生；不强行延寿凑剧情。

这些是手工编写并由状态选择的事件，不是无限生成剧情。四位同代人物是持续模拟实体，学堂来者/读者/后辈是事件角色，不宣称已实现完整家谱、社会政治或数万NPC。

## 原有规则继续有效

境界：凡人→炼气→筑基→金丹→元婴→化神→飞升。修为、灵石、体魄、调息和行动是突破的实际门槛；单次机会7%—90%，来自同一`breakthroughFactors`。失败保留一定修为并有伤势/调息，准备和已学本领改变实际结果。

不设置飞升率上限、死亡配额或跨局胜率调节。合理努力和际遇可能带来高成功率；不能为了多样结局安排强制失败。人生价值和差异不以最终境界评分。

年度顺序：年龄与行动恢复→日常方向安排→同道成长→时运→到期回响→重心收益与消耗→宗门/设施/供养/长期承诺/属性维护→准备→生死检查→重要事件选择→具备授权条件的日常突破→快照。任何待决事件或连续秘境中断推进。

五地域各四门派，实际入门条件、费用、年例、委托、专长、法宝由`sects.ts`定义；离宗失去当前供给与职级，保留所得，重复入宗不重复授予。多门专长同项收益取最强，不靠遍历无限堆叠。法宝单槽。

三种境界准备按对应重心与真实资源逐年积累，切换保留投入，失败不清空；完整准备成功破境可固化为本世本领。已完成准备不再把日常照料锁在该重心。

四段三幕地域机缘沿用已有同伴、技法、风险、退出与结果。入场占一次主动行动，后续不重复扣次数；进行中暂停年份和无关动作，存档可续。

原守望、问道、商路三条因果命途及旧事件继续；路线效果、绑定人物、回响和转向保持兼容。新增人物事件不删旧人物已经作出的承诺。

## 时间

`YearClock`仍按800年估算30／60分钟，1×每年2.25／4.5秒。1／2／4／8倍速只改变现实等待，不改变寿元或概率。没有直接跳年按钮，也没有离线收益。

人生页默认流转；换页、主要管理弹窗、隐藏标签和连续秘境会暂停。重要决定暂停等玩家，普通机缘只有在玩家打开代选时才代答。播放时间不包含阅读与操作，不强制在设定分钟数结束。

## 存档与确定性

存档仍为v1，原自动键、备份键、三手动槽与最多30卷前尘保持。新增direction可缺省且受枚举校验；所有新事件ID进入EVENT_MAP，使pending、seen和手动槽可继续校验。关系与承诺优先复用flags、seen、logs，没有另建存档数据库。

本地同种子、同动作与同设置可复现；运行中不使用Math.random。UI调用引擎动作，不能直接改Game。新人物/载入时取消不匹配的后台安排，不重复执行已保存的选择。

JSON导入先验证再确认，非法输入不能修改当前人物。老档不强行补演已经错过的早年事件；年龄上限限制相关开篇。不同站点/浏览器/设备不自动同步，需显式导出导入。

## 联网和公网发布

公网GitHub Pages使用`pages`构建模式，base为`/wanxian/`，图片路径与CSS随base正确定位。`__STATIC_HOSTING__`仅表示部署环境：该模式的模型客户端不请求不存在的API，设置明确显示本地概率模拟。它不改变核心玩法，不向浏览器注入密钥。

本地Vite dev／preview仍在5188提供可选StartLux同源接口。只对紧邻下一步的合法普通机缘或一次明确NPC互动候选排序；不控制重大事件、时钟、突破结果或奖励。未就绪即本地结算，迟到丢弃；取消、超时、断网和已发生结果的保存规则不变。服务器读取私有环境配置，前端不保存密钥。

源码main和静态发布gh-pages分离。工具`tools/publish-pages.ps1`只从已提交的干净工作区构建并普通快进推送；生成图片属于产品源素材，测试存档、日志、密钥与node_modules不发布。静态成品只发布到gh-pages。实际站点可用性必须以公网HTTP和真实浏览器验证，不用Git推送代替部署验收。

本轮不新增VPS服务、Cloudflare路由、常驻代理或ACP子Agent。

## 验证

必须运行生产构建、`npm test`和`npm run test:browser`。新增`tests/lifelines.test.ts`覆盖因果、失约、长期约束、死者身份、旧档和自动飞升边界；`tests/life-browser.mjs`覆盖默认出生、关系记忆、方向切换、旧档、刷新和多宽度两主题，并可直接验证静态发布目录或公网入口。

定向测试允许构造有效虚构人物来抵达具体边界；完整人生测试只调用实际引擎或加速浏览器时钟，不把测试中的代答行为宣传为游戏自动决定。既有导演测试显式把新人生事件标为已发生，以继续隔离并验证普通机缘预取，不能删除其断言。

用户主观乐趣与真机体验需要实际反馈，自动检查通过不等于已由用户验收。
